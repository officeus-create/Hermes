## 5. Historical / superseded material
Historical files remain useful for rationale and provenance, but they do not override the current owner decision or Brand System 2.0.

Examples:
- `hermes-connect/APPROVED_BRAND_SYSTEM_V1.md` — historical V1 baseline; its old knot-direction language is superseded by the later owner approval of Option 02.
- old visual experiment boards / motion explorations — evidence of exploration only unless explicitly referenced by a current decision document.

### Conflict rule
When two design documents conflict, use this precedence:
1. explicit later owner decision;
2. current production code/assets + verified merged evidence;
3. `HERMES_BRAND_SYSTEM_2_0.md` / current contracts;
4. current-state audits;
5. historical design documents;
6. exploratory boards/agent suggestions.

## 6. Owner-input queue
Do not block autonomous work on these; surface them when the owner is available:
- Beauty color / identity;
- visual choice of square app tile vs transparent standalone Option 02 in selected public contexts;
- approval of major redesigns that materially replace an already strong composition;
- any future change to Option 02 geometry.

## 7. External-access queue
- physical iPhone Safari/PWA check;
- physical Android install check;
- external account branding changes requiring authenticated account access;
- optional trademark/similarity review.

## Agent handoff rule
Before changing design:
1. read this index;
2. read the relevant current contract/audit;
3. classify the target as KEEP / FIX / REPLACE;
4. make the smallest systemic change;
5. validate with `DESIGN_REGRESSION_CHECKLIST.md`;
6. update evidence/lesson rather than starting a parallel design truth document.
