# Hermes SEO Framework

Canonical execution framework for Hermes search growth.

Updated: 2026-08-18
Canonical visual baseline: `77c8e549a55b9cd42694821675afd29ac8d7f123`
Shared SEO/GEO Design QA contract: GitHub issue #665

## Objective

Build one measurable system:

`crawl/index -> query ownership -> useful page -> qualified action -> delivered inquiry -> reviewed outcome -> evidence -> stronger SEO/GEO`

More URLs are not a success metric.

## Non-negotiable SEO rules

1. Do not create city, state, equipment, job, niche, or keyword-permutation pages only to increase URL count.
2. Every indexable URL needs a distinct purpose, enough useful main content, one canonical owner, and a valid internal path.
3. Priority commercial pages need an explicit next action and a measurable handoff path.
4. Unknown platform values stay unknown/null; never turn missing evidence into zero.
5. Sitemap presence, crawl discovery, or IndexNow submission are not proof of indexation or ranking.
6. Do not manufacture reviews, customers, statistics, capacity, rates, locations, affiliations, identities, or case results.
7. Do not expose private customer, carrier, shipment, lead, account, VIN, rate, invoice, document, credential, or live-position data for SEO/GEO.
8. External links must be legitimate and entity-relevant. No spam-link programs.
9. Do not rewrite an active search experiment before its planned comparable observation window unless a production defect requires it.
10. Every framework change must preserve build, regression tests, canonical ownership, privacy, conversion delivery, and Hermes Design OS.

## Mandatory CEO visual approval gate

A technically green PR is not visual approval.

If SEO/GEO work causes a noticeable visual change to layout, hero, cards, answer blocks, comparison surfaces, evidence/source modules, entity modules, imagery, 3D, color, typography, CTA presentation, animation, mobile composition, navigation, header/footer, or visual hierarchy:

1. Diagnose the user/SEO/conversion problem.
2. Build the best bounded version in a safe preview only.
3. Check desktop and at least 390px mobile.
4. Check SEO, schema, links, accessibility, performance, reduced motion, and responsive behavior.
5. Do not merge or publish the visual change.
6. Send the CEO a clickable preview URL.
7. State briefly what changed, why, what user problem it solves, and which action should improve.
8. Require explicit CEO approval.
9. Only after approval may that visual change merge to production.

Silence is not approval. CI green is not approval. Previous approval of the global design is not approval of a new visual page change.

Purely technical changes that do not noticeably alter presentation — canonical, metadata, schema, sitemap, broken links, hidden implementation defects, CI contracts — do not require a separate visual approval.

Design principles:

## Hermes Guided Action Loop

Every meaningful commercial surface should guide the user through:

`question -> self-recognition -> problem/opportunity -> understanding -> application to self -> one simple next action -> visible progress -> next step`

Use `ONE QUESTION -> ONE DECISION` where a user is selecting a route.

Prefer progressive disclosure, useful diagnostics, estimates, checklists, comparisons, recommendations, and low-friction next actions over walls of SEO copy.

## P0 — release and measurement foundation

### P0.1 Indexation integrity

Required:
- one HTTPS canonical owner per indexable page;
- sitemap URLs resolve to generated HTML;
- no `noindex` URL in sitemap;
- no duplicate sitemap ownership;
- robots and sitemap declarations stay aligned;
- redirect/error/demo surfaces do not become accidental commercial index inventory.

Repository enforcement includes existing sitemap, robots, production SEO hygiene, canonical and growth contracts.

### P0.2 Thin-page and duplicate guard

Required:
- no indexable sitemap page below the hard useful-content floor;
- thin pages are surfaced before any cluster expansion;
- exact normalized duplicate main content is blocked;
- mass locality/equipment/job/niche expansion is evidence-gated.

Framework enforcement:
- `scripts/hermes-seo-framework-p0-gate.test.mjs`

### P0.3 Conversion SEO

Priority money pages must preserve:
- sufficient decision content;
- clear H1/H2 structure;
- a detectable inquiry/action path;
- structured semantics;
- a truthful sales path and next best action.

Current priority set:
- `/logistics/appleton-wi-vehicle-transport/`
- `/logistics/dealer-vehicle-transportation/`
- `/logistics/car-hauling-dispatch/`
- `/logistics/auction-vehicle-pickup/`
- `/services/seo-for-logistics-companies/`
- `/services/seo-for-independent-auto-dealers/`
- `/services/seo/`
- `/services/local-seo/`
- `/services/website-development/`
- `/services/website-redesign/`

### P0.4 Technical foundation

Required:
- unique title/description/H1/canonical ownership;
- valid JSON-LD matching visible content;
- sitemap/robots consistency;
- HTTPS identifiers;
- no accidental duplicate canonical claims;
- performance and release checks remain green.

### P0.5 Measurement gate

Track where authenticated platforms expose the data:
- production status;
- index state;
- impressions;
- clicks;
- CTR;
- average position;
- landing/engaged sessions;
- CTA activity;
- delivered inquiry evidence;
- qualified inquiry evidence only after approved human/private review;
- next experiment/action and owner.

Do not create replacement analytics/search properties just to fill missing fields.

## P1 — GEO / AEO / entity reinforcement

### P1.1 GEO / AEO / LLM readability

Required:
- `llms.txt` and `llms-full.txt` stay factual and current;
- important services/entities are stated clearly in crawlable text;
- answer-oriented blocks answer real user questions directly;
- claims are supported by visible evidence or explicit boundaries;
- structured data matches visible content;
- definitions, process explanations, FAQs and first-party analysis beat keyword padding.

### P1.2 Internal linking

Required:
- one canonical owner per intent family;
- descriptive links reinforce real parent/child and commercial/resource relationships;
- do not add links merely to increase counts;
- orphan commercial URLs are release defects.

### P1.3 Entity / authority consistency

Required:
- Hermes entities stay disambiguated;
- names, canonical URLs, public contact facts and service descriptions stay consistent;
- `sameAs` is evidence-driven;
- third-party profiles represent the real entity.

### P1.4 Evidence-rich content

Prefer:
- permissioned case/proof assets;
- real named reviewer/expert only when approved;
- dated methodology;
- original tools/calculators where useful;
- public-safe first-party operational lessons;
- source and limitation notes for metrics.

Prototype = prototype. Demo = demo. Not configured = not configured.

### P1.5 Localization

Required:
- materially localized pages, not mechanical duplicates;
- valid self-canonical and hreflang relationships;
- locale/service combinations require real audience and content value;
- translation alone does not justify a new indexable URL.

## Definition of done for each SEO page

SEO is done only when the applicable page:
- can be found;
- is easy to understand;
- looks and behaves like Hermes;
- remains usable on desktop and 390px mobile;
- preserves schema/canonical/internal-link intent;
- gives the user one natural next step;
- keeps accessibility and performance intact;
- has no invented proof;
- has CEO approval if the change is visually noticeable.

## Current execution order

`P0 indexation -> P0 thin-page guard -> P0 conversion SEO -> P0 technical foundation -> P0 measurement -> P1 GEO/AEO -> P1 internal links -> P1 entity/authority -> P1 evidence -> P1 localization -> evidence-backed growth lanes`
