# Design dependency

The ecosystem-wide visual redesign is stage three, after Repair Shops and Academy have real user/revenue flows.

Reason: the shared design system should normalize proven product structures — navigation, account state, cards, forms, tables, progress, pricing, learning, booking, and mobile behavior — instead of forcing unfinished products into a visual shell.

Allowed before stage three: local UX fixes that directly improve activation, comprehension, conversion, mobile use, or payment/learning completion.

Deferred until stage three: broad cosmetic restyling that does not improve a measured Repair Shop or Academy funnel step.
