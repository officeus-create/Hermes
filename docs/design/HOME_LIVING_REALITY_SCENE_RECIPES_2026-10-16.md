# Home Living Reality — production scene recipes

Status: SELECTED / CODED IN BOUNDED SLICES / NOT A NEW HOME REDESIGN
Date: 2026-10-16

This file records implementation contracts for the current approved Home V4. It does not authorize a parallel shell, new canonical routes, customer claims, paid media generation, or production deployment.

## Shared contract

Every signature scene follows:

`purpose → story states → truth boundary → motion → mobile fallback → reduced-motion → performance → acceptance evidence`.

Primary rule:

`scene → life → event → Hermes reaction → human-understandable result → continuation`.

Key information remains semantic HTML. Video, WebGL, canvas, generated media and provider availability are enhancement layers only.

## Logistics — Spatial Operations

Purpose: make movement, environment and equipment feel physically separate.

Story states:
- equipment: car hauler / dry van / reefer / flatbed / step deck / hotshot;
- weather: sun / fog / dusk / rain;
- subject: one coherent primary logistics scene; no second standalone mini-truck overlay;
- operational meaning: request → route fit → human review → handoff.

Truth boundary: illustrative operating scene; no live loads, rates, capacity, tracking or customer data.

Motion:
- camera/background geometry remains locked;
- vehicle movement belongs inside an approved coherent scene/asset; do not simulate it with a second tiny HTML truck over another truck scene;
- weather changes on its own layer;
- desktop pointer/focus may nudge the world state;
- ambient equipment replacement runs more slowly than weather state changes.

Mobile fallback: one-column composition; ambient state cycle remains optional and must not alter layout geometry.

Reduced motion: stable sun state and no decorative weather/vehicle travel animation.

Performance: no runtime video-provider dependency. The fallback remains the local responsive WebP scene. One optimized local cinematic video may be added only after frame QA and provenance approval; it must be muted, playsinline, poster-backed, reduced-motion safe, and must never depend on a provider URL at runtime. Canvas remains unnecessary for Home.

Acceptance:
- 390 and 1440 no overflow;
- weather change must not replace the equipment image;
- rain uses distributed droplets/mist, never large translating glitch lines;
- background transform stays none;
- no standalone duplicate/tiny truck layer is present at any motion preference;
- no remote road/truck image layer or provider-hosted runtime media is present;
- if a cinematic video is later approved, exactly one local video layer is allowed and the integrated static scene remains the fallback.

## Marketing — Attention & Demand

Purpose: show the causal path from content creation to qualified business evidence.

Story:
`content/news → discovery/distribution → website action → inquiry/CRM evidence`.

Truth boundary: sanitized demonstration only; no invented reach, leads or revenue.

Current visual field: the retired botanical AI background is not loaded. The causal journey is the only visual proof until an owned/licensed human content-production clip or frame passes owner review and provenance.

Motion: current travels between real workflow stages; a future human micro-clip may be added only after owned/licensed assets pass provenance review.

Mobile: stacked causal sequence, not a shrunken desktop canvas.

Reduced motion: all stages remain visible and understandable without animated current.

## Technology — Systems / Build / QA

Purpose: show information moving through real Hermes products.

Story:
`Hermes Connect → Website Factory → Social Connectors → QA readback`.

Truth boundary: every status must remain LIVE / VERIFIED / DEMO / CONCEPT accurate. Deploy is never presented as live without readback.

Motion: data packet / system activity / QA verification only where it explains a real transition.

Mobile: simplified vertical system chain.

Reduced motion: static connected system map with the same labels.

## Academy — Human Progress

Purpose: preserve the approved warm Academy environment and express human progress through truthful progression states and restrained environmental motion.

Current implementation source lock: the owner-approved responsive Academy image family (`academy-512/887.avif|webp`) provides the visual environment: warm/light architectural study atmosphere, staircase/library context, daylight and the existing integrated book/page element. The generated learner-at-laptop derivative is not owner-approved and must not be loaded on Home. The progression UI is explanatory, not a replacement visual subject.

Story:
`Task → Practice → Feedback → Correction / Retry → Next step`.

Truth boundary: no guaranteed employment, income, completion or advancement.

Motion: this step does not add final Academy animation. Only restrained existing-safe atmosphere may remain when it does not alter the approved composition. Future movement may animate already-approved environmental elements only after visual approval; no new person, book, bookcase, page object, background or illustration is implied.

Mobile: preserve the same approved Academy environment with a simplified readable progression overlay.

Reduced motion: all progression labels remain readable; no decorative motion is required. Separate CSS book/bookcase objects, learner-primary overlays and stale page-turn/book-selection code are forbidden.

## Asset provenance gate

For every future video/3D/AI asset record:
- source;
- tool/model;
- ownership/license;
- commercial-output terms;
- approved/not approved;
- canonical exported copy;
- fallback poster/static layer.

Provider-generated media is an offline production input, never a website runtime dependency.
