# HERMES DIGITAL INTERFACE LAYER (HDIL)

**Status:** CANONICAL

**Scope:** Hermes digital communication surfaces  
**Parent standard:** `docs/design/HERMES_UNIFIED_BRAND_SYSTEM.md`  
**Owner:** Hermes Brand / Marketing / Product

## 1. Purpose

Hermes Digital Interface Layer (HDIL) is the digital-expression layer of the Hermes brand. It does **not** replace the Hermes Unified Brand System. It translates the existing pearl/ink, structured, operating-system language into social, messaging, bot, and digital communication formats.

The objective is simple: a person should recognize a Hermes message or card before reading the account name.

Hierarchy:

`Hermes Unified Brand System → Hermes Digital Interface Layer → channel mode`

HDIL has four execution modes:

1. **Full Terminal Mode** — text-first, fast-scanning channels.
2. **Adapted Interface Mode** — image/video-first social channels.
3. **Executive Interface Mode** — restrained B2B/professional presentation.
4. **Product-Native Mode** — website, Hermes Connect, Command Center and other functional interfaces.

---

## 2. Core visual grammar

Use the canonical brand tokens from the parent brand system. HDIL adds the following rules:

- Pearl / off-white foundation with black or ink typography.
- Monospace, pixel or terminal-inspired type is an **accent**, not the body font.
- Use terminal typography for short labels, product names, status codes, numbers, versions and compact headings.
- Keep paragraphs, instructions and long-form copy in a highly readable sans-serif typeface.
- Prefer thin rules, small state markers, compact labels, IDs, counters, progress indicators and modular interface-like cards.
- Use restrained canonical accent colors as identifiers or active-state signals; do not turn business-unit colors into large decorative panels.
- Design mobile-first. The primary meaning should be understood in approximately two seconds.
- One visual = one dominant message.
- Brand presence should come from structure and grammar, not from repeated large logos.
- Preserve whitespace. Avoid decorative overload.

### Avoid

- Pixel/mono body text for long paragraphs.
- Generic cyberpunk, neon, hacker or gaming aesthetics.
- Heavy gradients used only for decoration.
- Large blocks of arbitrary department color.
- Tiny metadata that cannot be read on a phone.
- Turning every photograph or human story into a fake terminal screenshot.
- Creating a second visual system that conflicts with the canonical Hermes brand tokens.

## 3. Channel policy

### A. FULL TERMINAL MODE — DEFAULT / REQUIRED

#### Telegram
Use HDIL Full Terminal Mode for:

- group and channel post graphics;
- bot cards and bot-generated visual messages;
- pinned-message covers;
- task cards;
- knowledge cards;
- status / release cards;
- KPI and result cards;
- link-preview artwork when Hermes controls the preview asset;
- onboarding and system notices.

Telegram is the strongest natural fit because it is both a communication channel and an operational workspace. Hermes content should feel like an interface inside the Hermes Operating System rather than a generic social post.

#### X / Twitter
Use Full Terminal Mode as the default Hermes visual wrapper for:

- product/status updates;
- short data cards;
- launch/release notes;
- operational observations;
- educational threads with supporting visuals;
- KPI / result proof;
- branded quote or statement cards.

Native text posts do not need artificial decoration. The HDIL signature applies to attached graphics, recurring content structures and the account's visual language.

#### Threads
Use Full Terminal Mode under the same principle as X, with slightly more conversational copy where appropriate. It is especially suitable for:

- fast observations;
- mini case studies;
- results;
- short educational sequences;
- build-in-public updates;
- Hermes Academy and Hermes Connect knowledge fragments.

**Rule:** Telegram + X + Threads form the primary HDIL Full Terminal Mode cluster.

---

### B. ADAPTED INTERFACE MODE

#### Instagram
Do **not** force Full Terminal Mode onto the entire Instagram feed. Use an adapted version for:

- Reel covers;
- carousel covers and information slides;
- product/system announcements;
- Academy educational posts;
- case-study results;
- status, KPI and proof cards;
- Stories that behave like system cards.

Keep photography, people, places, emotion and video content visually native where that produces a stronger story. The HDIL elements act as recognizable packaging: label, status line, frame, small mono heading, pearl/ink hierarchy, interface marker.

#### Facebook
Use Adapted Interface Mode for:

- link-preview artwork;
- product and company announcements;
- educational cards;
- events;
- case studies;
- KPI/result proof;
- system or hiring notices.

Do not make every human/community post look like a software console. Facebook should retain more native editorial and human content while inheriting Hermes structure where useful.

#### TikTok / short-video surfaces
Use native human/video presentation with an HDIL wrapper:

- hook/title frame;
- small system/status markers;
- chapter labels;
- proof/result cards;
- CTA/end frame.

Do not turn the entire video into terminal UI. Human speech, demonstrations and real environments should remain native.

---

### C. EXECUTIVE INTERFACE MODE

#### LinkedIn
Use a restrained business variant:

- pearl/ink base;
- minimal mono labels;
- clean data/status blocks;
- business evidence;
- restrained terminal/pixel styling.

The result should feel enterprise and operational, not retro or playful.

---

### D. PRODUCT-NATIVE MODE

Applies to:

- Hermes website;
- Hermes Connect;
- Command Center;
- dashboards;
- internal operating interfaces.

These products are the source of the interface language. They may share HDIL grammar — labels, state markers, pearl/ink hierarchy, compact metadata — but should remain functional product interfaces. Do not skin the entire product as a decorative retro terminal.

## 4. Standard content archetypes

All teams and bots should prefer a small reusable set of content structures:

1. **ANNOUNCEMENT** — launch, update, important notice.
2. **TASK** — assignment, owner, deadline, expected evidence.
3. **KNOWLEDGE** — lesson, instruction, concept, playbook fragment.
4. **STATUS** — LIVE / TESTING / BLOCKED / PENDING / DONE.
5. **RESULT** — KPI, case, evidence, before/after, completed work.
6. **ALERT** — action required or risk.
7. **DECISION** — approved operating or product decision.
8. **RELEASE** — shipped change, version, affected surface.

Recommended interface labels where relevant:

`STATUS` · `OWNER` · `DEADLINE` · `VERSION` · `EVIDENCE` · `NEXT` · `LIVE` · `TESTING` · `BLOCKED` · `DONE`

Do not add metadata that does not help the reader act or understand.

## 5. Minimum anatomy of a Hermes digital card

A card normally contains:

1. small Hermes / business-area identifier;
2. short archetype label or status;
3. one dominant headline;
4. one key fact, instruction or result;
5. optional action / deadline / evidence line;
6. restrained interface accent.

Example structure:

```text
HERMES / ACADEMY

TASK 014
STATUS: ACTIVE

5-MINUTE ASSIGNMENT

Current status
Real user
Problem solved
Evidence required

DEADLINE 16:00 CT
```

The example is a structural model, not a requirement to render every post as literal text.

## 6. Cross-channel content flow

One approved information unit may be transformed into multiple channel-native outputs without changing factual truth:

`SOURCE FACT / DECISION / RESULT → Telegram operational card → X concise public proof/update → Threads conversational insight → Instagram adapted visual/carousel → Facebook adapted editorial card → LinkedIn executive evidence → Website/Connect native product state where applicable`

The wording, crop, visual density and CTA may change by channel. The underlying factual claim and evidence may not.

Do not interpret this as permission for blind mass cross-posting. Each output should be channel-native and must follow the applicable publishing/approval process.

### GitHub
This document is the canonical, version-controlled HDIL specification. Product and code changes should reference this file instead of inventing local visual rules.

### Google Drive
Drive documentation and operating playbooks mirror the owner decision and reference this GitHub standard. The canonical business-readable mirror is `HERMES DIGITAL INTERFACE LAYER — CHANNEL STANDARD — CURRENT`. Drive is an operating/reference layer, not an independent competing brand specification.

### ClickUp
Implementation work should be tracked as tasks/checklists/evidence. ClickUp should point to the canonical standard and should not become a second copy of the design system.

### Cloudflare
Cloudflare is a delivery/production surface, not a separate brand source of truth. Pages and applications deployed through Cloudflare must inherit the implementation from the governed repository and canonical Hermes tokens. Do not maintain a divergent Cloudflare-only visual rule.

Cloudflare-specific work remains delivery, routing, security, performance and runtime work; design truth remains in GitHub/One Brain.

### ChatGPT / Hermes AI workflows
When generating or reviewing Telegram, X, Threads, Instagram, Facebook, LinkedIn, TikTok/short-video, bot or social-system assets, apply this channel matrix by default unless an explicit current campaign requirement overrides the treatment.

## 9. Acceptance test

A new Hermes digital asset passes HDIL when:

- it is recognizable as Hermes without relying on a giant logo;
- it uses canonical brand tokens;
- it remains readable on a phone;
- the content type/status is immediately understandable;
- terminal typography is restrained and functional;
- one primary message dominates;
- the platform mode in the matrix is respected;
- factual claims remain evidence-bounded;
- it does not look like generic cyberpunk or an unrelated template pack.

If any of these fail, revise before publishing.

---

## 10. Operating rule

Default to HDIL whenever generating or reviewing Hermes digital communication assets.

- **Telegram + X + Threads:** Full Terminal is the default/required visual mode.
- **Instagram + Facebook:** Adapted Interface is the default.
- **LinkedIn:** Executive Interface.
- **TikTok/short video:** native video with HDIL framing.
- **Website / Hermes Connect / Command Center:** Product Native.

An explicit current owner directive may override a channel treatment for a specific campaign, but should not silently create a competing design system.
